Google Drive Picker en Producción + Persistencia Firestore de Carpeta Activa
Problema
Google Picker no abre en producción porque las variables de entorno VITE_GOOGLE_PICKER_* no están definidas en ningún archivo .env. El build desplegado inyecta "" en las tres constantes, haciendo que pickerDisponible sea siempre false. El botón "Seleccionar carpeta en Drive" queda deshabilitado con el mensaje: "Google Picker pendiente de configurar".

Además, la carpeta activa se persiste solo en localStorage, lo que significa que un segundo admin del mismo tenant no ve la carpeta ya seleccionada. Esto es un problema real en escenarios multi-admin.

Carpeta solo en localStorage
La carpeta activa se guarda en localStorage["tudojang:driveFolder:<tenantId>"]. Esto funciona para un solo admin en un solo navegador, pero:

Si Admin B se conecta desde otro dispositivo, no ve la carpeta seleccionada por Admin A
Si se borra caché del navegador, se pierde la carpeta activa

IMPORTANT

Google Picker API habilitada: Verificar en Google Cloud Console > APIs que la Google Picker API esté habilitada. Sin esto, Picker no abre aunque las variables estén bien.

WARNING

Restricciones de API key: La API key pública debe tener el origen https://tudojang.com y https://tudojang.web.app como referrers HTTP permitidos. Si la key solo tiene restricciones para Firebase APIs, el Picker será rechazado.

Open Questions
IMPORTANT

¿Persistir carpeta en Firestore? El doc de cierre (punto 4 de pendientes) sugiere evaluar esto. Mi recomendación: SÍ, porque:

Multi-admin por tenant necesita carpeta compartida
El campo folderId ya encaja naturalmente en el documento driveConnections existente

Propuesta: Al seleccionar carpeta, guardar folderId en tenants/{tenantId}/driveConnections/{connId}. Al cargar BibliotecaView, leer primero de localStorage (cache rápido), luego sincronizar desde la Cloud Function. ¿Aprobás esta dirección?
